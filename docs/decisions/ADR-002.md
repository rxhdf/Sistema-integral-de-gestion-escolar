# ADR-002: Alcance del MVP limitado a Expediente_Academico

**Estado:** Aceptado
**Fecha:** 2026-07-29

## Contexto

El modelo conceptual completo define 3 expedientes por alumno
(`Expediente_Personal`, `Expediente_Academico`, `Expediente_Escolar`), además
de `Familia`, `Tutor`, `Asistencia`, `Accidente_Escolar` y
`Problema_Salud`. El MVP se definió con el criterio: "¿sin esta entidad,
puedo o no puedo guardar un expediente de alumno y una calificación con
integridad referencial?".

## Decisión

El MVP incluye únicamente `Expediente_Academico`. Quedan explícitamente
diferidos a fases posteriores:

- `Expediente_Personal`, `Expediente_Escolar`
- `Familia`, `Tutor`
- `Asistencia`, `Accidente_Escolar`, `Problema_Salud`
- `Institucion`, `Turno` como tablas separadas (colapsados en `Plantel`/`Grupo`)
- Roles como tablas separadas (`Director`, `Subdirector`,
  `Orientador_Educativo`, `Docente`) — ver ADR-003

## Razón

Estas entidades enriquecen el expediente del alumno pero no son necesarias
para el flujo mínimo verificable: dar de alta un alumno, inscribirlo a un
grupo, y capturar/consultar su calificación. Incluirlas en el MVP retrasa la
primera validación con usuario real sin agregar valor al flujo crítico.

## Alternativas descartadas

- **Incluir los 3 expedientes desde el MVP**: descartado por alargar el
  tiempo a primera validación sin aportar al flujo mínimo de calificaciones.

## Consecuencias

- El diccionario de datos y el DDL del MVP solo contemplan las 10 entidades
  documentadas en `docs/data-dictionary/mvp.md`.
- Cuando se implemente `Expediente_Personal`/`Expediente_Escolar` en una
  fase posterior, deben mantener la misma relación 1:1 con `Alumno` y el
  mismo criterio de separación por tabla que `Expediente_Academico`
  (ver ADR-001), para preservar la coherencia de RLS.
