# ADR-003: Roles colapsados en campo `Personal.rol` (3 valores)

**Estado:** Aceptado (actualizado)
**Fecha:** 2026-07-29
**Actualiza:** decisión original de 2 roles (`docente`, `directivo`),
ampliada a 3 (`docente`, `directivo`, `admin`) tras definir la matriz RBAC.

## Contexto

El modelo conceptual completo define roles como tablas separadas:
`Director`, `Subdirector`, `Orientador_Educativo`, `Docente`, cada una con
posibles atributos propios. Para el MVP se evaluó colapsar estos roles en
un solo campo de `Personal`.

## Decisión

Se modela un único campo `Personal.rol` con `CHECK IN ('docente',
'directivo', 'admin')`, en vez de tablas de rol separadas.

Jerarquía de permisos (ver `docs/rbac/matriz-rbac-mvp.md`):
`admin` ⊇ `directivo` ⊇ `docente` en todo lo académico/operativo. La única
diferencia entre `admin` y `directivo` es la gestión de cuentas de
`Personal` (crear, editar rol, dar de baja — incluyendo directivos).

## Razón

Para el MVP, con un solo plantel y 3 roles funcionales sin atributos
adicionales propios de cada rol (ej. `Director` no necesita hoy campos que
`Docente` no tenga), una tabla de roles separada agrega complejidad sin
beneficio inmediato. Un campo enum es suficiente para soportar toda la
matriz RBAC definida.

## Alternativas descartadas

- **Tablas separadas por rol** (`Director`, `Docente`, etc.): descartado
  para el MVP por complejidad innecesaria dado que ningún rol tiene hoy
  atributos propios que no quepan en `Personal`.

## Consecuencias (deuda técnica documentada intencionalmente)

- Si en una fase posterior se necesitan atributos específicos por rol (ej.
  un `Orientador_Educativo` con `grupos_asignados` de tutoría, distinto de
  `Grupo_Asignatura` docente), la migración de "campo enum" a "tablas de rol
  separadas" es un cambio de esquema real, no trivial. Debe planearse como
  migración explícita, no como parche.
- Regla de negocio pendiente de implementar en el service (no en RLS ni en
  constraint de tabla): impedir que el único `admin` activo se dé de baja a
  sí mismo o cambie su propio rol, para evitar dejar el sistema sin ningún
  admin.
